# Mazochist

A maze game where every maze is solvable and none of them feel it.

The design rule, from [DESIGN.md](DESIGN.md):

> The difficulty comes from **information denial and decision cost**, not motor
> control. If a modifier can be overcome by "just being more careful with the
> controls", it's motor difficulty. Kill it.

## Running it

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # engine, level codec, and every level played to completion
npm run lint
npm run build
```

## How it is put together

```
src/
  engine/          no React in here
    game.js        game state and one fixed step of simulation
    loop.js        fixed-timestep loop — simulation speed is not refresh rate
    physics.js     ball movement and collision, in cell units
    levelFormat.js the level codec, used by both saved levels and shared URLs
    obstacles.js   the obstacle registry, and the retired list
    scene.js       composes one frame
    renderer.js    the only module that thinks in pixels
  hooks/           the bridge between the engine and React
  components/      presentation
ml/
  simulate/        simulated player and difficulty metrics
  evolve/          evolutionary maze search
  train/           VAE maze generation, PPO obstacle placement
  export/          level export, format migration, rebalancing
```

Two rules keep the engine honest:

**Simulation advances on a fixed timestep.** `physics.js` works in cell units
and `loop.js` steps it in fixed `1/60s` chunks regardless of how often the
browser paints. Rendering follows the display; difficulty does not.

**React renders about ten times a second.** The game object is mutable state
owned by a ref and driven by `requestAnimationFrame`. `useGameLoop` publishes a
small flat snapshot for the HUD and nothing else crosses the boundary.

## Obstacles

Every obstacle hides information, deceives, or forces a commitment.

| | Obstacle | What it costs you |
|---|---|---|
| **Hide** | fog of war | you cannot plan, only explore and remember |
| **Hide** | traps | invisible until they kill you, then you have to remember where |
| **Hide** | memory wipe zones | erases everything you have mapped |
| **Deceive** | false exits | looks like the way out, sends you back to the start |
| **Deceive** | mimics | drawn by the same code as the real exit; touching one is death |
| **Deceive** | liar walls | the wall you see is not the wall that is there |
| **Commit** | one-way gates | close behind you |
| **Commit** | the apparition | retraces your exact path ten seconds late |
| **Commit** | the void | eats the maze outward from the start |

`engine/obstacles.js` also carries `RETIRED_MODIFIERS` — ice, gravity, reverse,
spinners, slide walls, fat cursor, fart tiles, teleporters, blackout. These were
motor difficulty. The test suite fails if any of them turn up in a level again.

## Levels

28 levels: 3 hand-crafted in `engine/levels.js`, 25 curated in
`public/levels/curated.json`.

The curated set is generated by the Python pipeline and rebalanced by
`ml/export/rebalance.py`, which is deterministic — seeded per level by name, so
re-running it reproduces the same set. It places obstacles against the solution
path (deception on it, lethality only off it), then re-checks every level for
solvability with gates treated as immediately one-way, which is stricter than
the game itself.

`src/engine/autoplay.test.js` then drives every level to completion with the
real physics engine, so "solvable" means the ball can actually walk it and not
merely that a graph search found a route.

## Level format

Levels are a compact array-of-arrays, v2:

```
[x, y, wallBits, modifier, flags, gateDir, liarBits]

wallBits  top 1, right 2, bottom 4, left 8
flags     trap 1, mimic 2, memoryWipe 4
liarBits  sides whose visual is inverted from reality
```

v1 decodes without a shim: it wrote `trap` as 0/1 where `flags` now has its trap
bit, and a missing 7th element is 0. `ml/export/migrate_to_v2.py` upgrades old
files, recovering obstacles that v1 had stranded in the `modifier` slot.
